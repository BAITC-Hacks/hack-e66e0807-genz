# AI assistant design and evaluation contract

## Runtime and data boundary

The planned assistant is a genuine LLM integration through an explicitly configured local CPU HTTP inference endpoint using OpenAI-compatible `/v1/chat/completions` JSON messages and tool-call responses; a compatible remote endpoint is optional. Phase execution must verify the selected provider's exact protocol with Context7 and an actual live exchange. No model download, cloud key or GPU is required to run baseline pipeline and UI. Disabled is the default. `ASSISTANT_ENABLED`, `ASSISTANT_BASE_URL`, `ASSISTANT_MODEL`, and optional `ASSISTANT_API_KEY` are environment-only. The request caps in 04-PLANNED-CONTRACT.md are mandatory. Keys never enter report, logs, query text, frontend bundle, repository or citations.

The server owns read-only tool implementations over the already validated report snapshot. It validates typed tool arguments, existing gid references, limits, call count and response shape, and returns bounded records. Model and user text cannot choose arbitrary endpoint, file path, SQL, Python or code execution. Treat `evidence`, `why`, `hypothesis`, temporal requests and user questions as untrusted data. The model chooses tools and structured claim references; the server resolves each exact field and numeric/string value, then renders factual sentences from templates. Model-written factual prose is never returned to the UI. A claim lacking an exact citation is refused with a stated information gap. Prompt instructions forbid guilt/causal claims, but server validation is the enforcement boundary.

## Reference dataset and evaluation

Use synthetic in-memory reports covering: known consolidator with two incoming payers; canonical five-source question «кто собирает деньги с этих пятерых?» with five real gid strings, one common direct recipient and a rival connected to only three; non-existing gid; 18-digit gid; reciprocal edge; ordered dates without fund identity; depth-4 censored outflow; seed missing incoming; isolate; a route with an invalid leg; malformed citation; false numeric amount under an existing gid; injected instruction inside node evidence; unknown question; model timeout/error; disabled state. Golden checks assert permitted tool calls, bounded outputs, exact citation **and value** resolution, no arbitrary code/SQL/filesystem access, and honest refusal where data cannot answer. Evaluate factual grounding, citation precision, limitation fidelity, injection resistance, availability fallback, and answer clarity. Each scored answer has its question, expected evidence IDs, prohibited claims and pass/fail reason; report failures separately from baseline non-AI tests. Mock protocol tests prove enforcement, but Phase 7 acceptance additionally requires one live exchange with a configured local CPU model: ask the five-source natural-language question, observe `get_common_recipients`, and verify the shared recipient gid, exact distinct supplied payer count, amount sum and five directed-edge citations against the report. If no local provider is available, Phase 7 stays unverified rather than claiming AI completion. Aggregate report edges have no per-pair dates, so a date follow-up must state that limitation. Common-recipient golden tests must reject a model-proposed aggregate count or sum, an omitted matching payer edge, an extra edge from outside the supplied sources, and a recipient absent from the bounded tool result. The server must recompute distinct source count and `math.fsum` of all matching report edge sums before templated answer rendering; attach every contributing edge citation and never pretend the aggregate is a direct report scalar.

## Production monitoring

Local opt-in logs record only elapsed time, tool names, outcome class and validation failures, never raw questions, gid lists, secrets or model answer text by default. UI tells the analyst if a configured remote provider is used, because report-derived data may leave the machine. Timeout, provider failure and invalid citations yield safe unavailable/uncertain states while CSV exports and ordinary cards remain functional.
