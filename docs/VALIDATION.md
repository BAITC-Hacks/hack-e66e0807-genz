# Проверка результата на данных кейса

Этот документ фиксирует **измеренные** результаты для предоставленных трёх parquet. Проверки выполнялись 23 сентября 2026 года. Числа относятся к этой выгрузке и изменятся при других входных файлах. Роли, аномалии и маршруты — гипотезы для ручной проверки, не доказательство причастности или движения одних и тех же денег.

| Критерий кейса | Наблюдаемый результат | Проверка |
| --- | --- | --- |

| Роли с обоснованием | Каждому узлу назначена одна из шести ролей, ограниченные оценки 0–1 и текст причины не длиннее 200 символов. | Валидатор проверяет все 2 248 записей. Правила, пороги и порядок их применения описаны в [методике](METHODOLOGY.md). |

Финальная проверка одной командой `python3 run.py --skip-install --check` прошла; два независимых запуска CLI заняли **4,525 и 4,277 с**, существенно ниже ограничения кейса в 300 с. Это замер на текущей машине, а не гарантия времени на любом оборудовании. Три CSV побайтно совпали с сохранённым результатом до дополнительных аналитических функций (сохранённой перед расширением).

Отдельный валидатор `scripts/verify_extensions.py` заново читает parquet и проверяет содержимое каждого опубликованного маршрута, цикла, сценария устойчивости и аномального признака; последний запуск с сохранённой базой CSV завершился `PASS`. Девять адресных тестов проверяют порядок дат и усечение, канонизацию циклов, удаление узлов, пустой граф, самооперации и граничные группы сравнения.

## Как воспроизвести проверку

После установки зависимостей и расчёта через `python3 run.py --check` можно отдельно выполнить:

```bash
.venv/bin/python scripts/verify_temporal.py --data FINANCE-CASE/data --out output
.venv/bin/python scripts/verify_extensions.py --data FINANCE-CASE/data --out output
.venv/bin/python -m unittest discover -s tests -v
npm --prefix frontend test -- --run
npm --prefix frontend run build
```

После заморозки интерфейса независимый повторный запуск браузерных сценариев на реальном отчёте прошёл:

Проверены новые снимки рабочего стола, выбранной связи, таблицы переводов, маршрутов, устойчивости и мобильного экрана ([широкий экран](screenshots/desktop-selected-edge.png), [узкий экран](screenshots/mobile-workspace.png)). На широком экране одновременно видны очередь, направленная схема с суммами и карточка узла; выбранная связь раскрывает отправителя, получателя, точную сумму и количество переводов. На ширинах 390 и 304 px выбранный gid, входящие/исходящие, суммы и ссылка на основание остаются доступны; в обоих случаях страница не выходит за пределы ширины. Автоматические проверки подтверждают доступность функций, а не заменяют личную оценку удобства аналитиком.

Финальная сборка фронтенда и **33 теста** прошли; проектный прогон Python-тестов дал **42 PASS**. Независимые расчётные валидаторы выше запущены отдельно и прошли. Исходный код расчёта и интерфейса проверен на зашитые 16-значные gid: таких списков результатов нет. Архив исходников и локальный запуск документированы в [README](../README.md); испытание установки с нуля на другой операционной системе не проводилось.

AI-ассистент — необязательная возможность. На момент этой проверки нет подтверждённого реального ответа через настроенного провайдера с проверенными ссылками на отчёт, поэтому его готовность **не заявляется**. Без настройки провайдера основной граф, расчёт и выгрузки работают независимо от него.
