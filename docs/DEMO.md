# Демо на пять минут

До начала: три parquet организаторов находятся в `FINANCE-CASE/data/`, терминал открыт в корне проекта, установлены Python 3.12+ (кроме 3.14.1) и Node.js 22.12+ с npm. Для живого показа запустите `python3 run.py` и откройте http://127.0.0.1:8000. На подготовленной машине можно использовать `python3 run.py --skip-install`. При первом запуске установка пакетов требует интернета. Ниже приведены реальные `gid` из текущего `output/report.json`; при смене входных файлов выберите примеры заново.

**0:00–0:40 — живой расчёт.** Покажите вывод `python3 run.py` (сборка, расчёт и локальный адрес). Для отдельного повторного расчёта при уже открытой странице выполните в другом терминале:

```bash
.venv/bin/python -m solution --data FINANCE-CASE/data --out output
```

Обновите страницу: 2248 узлов, 3119 рёбер, 4840 транзакций. Аналитик получает очередь проверки по объяснимым признакам; балл не является вероятностью вины.

**0:40–2:00 — приоритетный структурный посредник.** Найдите `100000008346837100`. Это №1 в текущем топе: приоритет `0.837198`, гипотеза `coordinator`, `depth=2`. Девять входящих контрагентов, 25 исходящих, пути от семи seed; вход 254 359 KZT, выход 1 258 643 KZT. Покажите стрелки связей и раздел «Временные признаки»: 12 исходящих переводов через день после наблюдаемого входа; 13 — через 1–2 дня (второе число включает первое). **20 июля** видны поступления от четырёх разных плательщиков на 64 300 KZT. Это совпадения дат, не прослеживание конкретных денег. Выход больше входа, потому что наблюдаемая выборка не является полным балансом. Покажите предлагаемый запрос точного времени и выписки для проверки гипотезы.

**2:00–3:00 — обрыв сети.** Найдите `100000003037476100`. Это `depth=4`, три входящих контрагента, вход 555 000 KZT за два активных дня, медиана одного входящего перевода 95 000 KZT; нулевой наблюдаемый выход. Роль `consolidator`, `role_score=0.65`. Покажите профиль входящих, фильтр «Граница выгрузки» и предупреждение карточки. Нулевой выход **не** даёт роль `terminal`: продолжение переводов за четвёртым коленом не наблюдается. Пути ведут от восьми seed; следующий шаг — запросить дальнейшие исходящие.

**3:00–3:35 — сохранённый изолят.** Найдите `100000000456947100`. Это seed без наблюдаемых связей, `peripheral`, приоритет 0, коэффициент пропуска отсутствует. Узел остаётся в таблице и поиске; карточка предлагает запросить входящую историю. Отсутствие видимых связей — нехватка данных, а не вывод о клиенте.

**3:35–4:25 — произвольный gid и сообщества.** Предложите жюри выбрать любой `gid` из CSV. Вставьте его целиком в поиск, откройте карточку и окрестность. Фильтр списка не ограничивает поиск. Покажите сообщество, его размер, число seed и внутреннюю сумму; скачайте три CSV. 91 сообщество Louvain и 35 компонент связности, включая 19 изолятов, — разные разбиения.

**4:25–5:00 — воспроизводимость и пределы.** Покажите `python3 run.py --check`, формулу приоритета в README и три фиксированных CSV. Доступны только исходящие внутрибанковские переводы июля от 5000 KZT до `depth=4`; входы seed неполны. Следующий шаг аналитика — запрос более полной истории и ручная проверка гипотез.

## Как выбрать примеры после смены входов

Идентификаторы выше получены из фактического `output/report.json`, а не используются в аналитических правилах. При другом наборе пересчитайте и выберите первый top, первый граничный узел с несколькими входами и первый изолят:

```bash
.venv/bin/python -c 'import json; r=json.load(open("output/report.json")); print("top:",r["top_nodes"][0]["gid"]); print("boundary:",next((n["gid"] for n in r["nodes"] if n["boundary_censored"] and n["in_degree"]>2),"нет примера")); print("isolate:",next((n["gid"] for n in r["nodes"] if n["in_degree"]+n["out_degree"]==0),"нет примера"))'
```

При отсутствии нужного типа узла сообщите это; не подставляйте синтетические сведения в живое демо.
