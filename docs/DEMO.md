# Демо на пять минут

До начала: зависимости установлены, `npm --prefix frontend run build` выполнен, терминал открыт в корне проекта. Используйте реальные parquet организаторов. Заранее запустите сервер по README; интерфейс можно обновить после повторного расчёта.

**0:00–0:40 — живой расчёт.** Выполните:

```bash
.venv/bin/python -m solution --data FINANCE-CASE/data --out output
```

Покажите 2248 узлов, 3119 рёбер, 4840 транзакций; откройте localhost:8000 и обновите страницу. Объясните: это локальная эвристическая модель проверки структуры, а не вероятность вины.

**0:40–1:50 — приоритетный структурный посредник.** Найдите `100000008346837100`. В проверенном результате это первый приоритет: `0.837198`, гипотеза `coordinator`, depth=2. Девять входящих контрагентов, 25 исходящих, направленные пути от семи seed; вход 254 359 KZT, выход 1 258 643 KZT. Покажите карточку и направление связей. Выход больше входа: наблюдаемая выборка не является полным балансом. Термин «координатор» описывает структурную гипотезу, не подтверждённую личную роль.

**1:50–2:50 — обрыв сети.** Найдите `100000003037476100`. Это depth=4, три входящих контрагента, вход 555 000 KZT, нулевой наблюдаемый выход; роль `consolidator`, `role_score=0.65`. Покажите предупреждение границы. Нулевой выход не даёт роль terminal: продолжение переводов лежит за границей выгрузки. Пути ведут от восьми seed; это основание расширить запрос данных.

**2:50–3:25 — сохранённый изолят.** Найдите `100000000456947100`. Это seed без наблюдаемых связей, `peripheral`, приоритет 0, коэффициент пропуска отсутствует. Узел остался в таблице и поиске. Отсутствие связей означает отсутствие структурных данных, не оправдание и не обвинение.

**3:25–4:20 — произвольный gid и сообщества.** Предложите жюри выбрать любой `gid` из CSV. Вставьте его целиком в поиск, откройте карточку и окрестность. Покажите сообщество, его размер/seed/внутреннюю сумму; скачайте три CSV. Объясните 91 сообщество Louvain и 35 компонент связности, включая 19 изолятов: это разные разбиения.

**4:20–5:00 — воспроизводимость и ограничения.** Покажите формулу приоритета в README, детерминированные выгрузки, отчёт проверок. Укажите июль, один банк, порог 5000 KZT, неполноту входов seed и обрыв depth=4. Следующий аналитический шаг — запрос более полной истории и ручная проверка гипотез, а не автоматическое обвинение.

## Как выбрать примеры после смены входов

Идентификаторы выше получены из фактического `output/report.json`, а не используются в аналитических правилах. При другом наборе пересчитайте и выберите первый top, первый граничный узел с несколькими входами и первый изолят:

```bash
.venv/bin/python -c 'import json; r=json.load(open("output/report.json")); print("top:",r["top_nodes"][0]["gid"]); print("boundary:",next((n["gid"] for n in r["nodes"] if n["boundary_censored"] and n["in_degree"]>2),"нет примера")); print("isolate:",next((n["gid"] for n in r["nodes"] if n["in_degree"]+n["out_degree"]==0),"нет примера"))'
```

При отсутствии нужного типа узла сообщите это; не подставляйте синтетические сведения в живое демо.
